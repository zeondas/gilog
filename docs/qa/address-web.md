## 3. 개인정보 – 위치만 보내도 되나

- 보내는 것: 위치 칸의 **주소 부분만**("파주시 통일로 138"). 뒤 글("앞", "일원")·민원 내용·민원인 이름·연락처는 붙이지 않아요. 지금 규칙(이름·연락처는 구글로 안 보냄)과 부딪히지 않아요.
- 위치는 보통 "고칠 곳"이지 민원인 집이 아니지만, 집 앞 민원도 있어 완전히 남의 일은 아니에요.

**1안 – 행안부(주소정보누리집)에만, 주소 글만.** 원래 이 주소를 만든 정부 기관이라 새로 알려 주는 것이 없어요. 민간 회사는 안 써요.
**2안 – 행안부 + 카카오(또는 네이버)도 허용, 주소 글만.** 결과를 둘로 맞대 볼 수 있지만 민원 위치가 민간 회사 기록에 남아요.

권함: 1안 – 얻는 것(맞대 보기)보다 나가는 곳이 늘어나는 것이 더 커요. 규칙 한 줄: "민원 위치는 주소 글만 행안부 주소 검색으로만 보낼 수 있어요."

## 4. 합치는 순서

**1안 – 내장 먼저, 표에 없을 때만 웹.**
- 표에 딱 맞으면 지금처럼 바로 바뀌어요(웹 안 감, 오프라인 됨).
- 표에 없는 번호·없는 도로·파주 밖일 때만 웹에 물어요. 웹이 맞는 주소를 주면 후보 목록 맨 위에 "웹" 배지로 먼저 골라 두고, 아래는 지금의 가까운 번호 3개("내장" 배지). 웹이 안 되면 지금과 똑같아요.
- 파주 밖: 웹 결과를 후보로만 보여요(저절로 바꾸지 않음), 지역 칸은 비움.
- 다를 때: 생기지 않아요(표에 있으면 웹에 안 물음). 행안부 같은 자료의 옛판과 새판이라 표에 있는 건 거의 맞아요.

**2안 – 웹 먼저, 실패·오프라인이면 내장.**
- 모든 주소를 웹에 먼저 물어요 – 매번 잠깐 기다리고, 엑셀 가져오기는 줄 수만큼 나가요.
- 다를 때: 웹(새판)을 믿고, 두 답이 다르면 둘 다 출처 배지로 보여 사용자가 골라요.

시안: 판 `AddressWeb.dc.html` – 지금 / 1안 / 2안 + 설정 카드.

## 5. 갱신

- 웹이 되면 분기 수동 갱신을 **없앨 필요는 없고 줄일 수 있어요** – 표가 낡아도 빠진 곳은 웹이 메워요. 반기나 1년에 한 번이면 충분해요.
- 앱이 전체자료를 스스로 받아 표를 바꾸는 방식은 권하지 않아요: 자동으로 받는 공개 주소를 찾지 못했고, 파일이 크고, 앱이 직접 나가는 길이 회사에서 막혔던 길이에요.
- 대신 **빌드 없이 표를 바꾸는 길**: 설정에서 사용자가 받은 경기도 파일을 고르면 앱이 파주시 줄만 뽑아 저장(지금 `extract.py`가 하는 일을 앱이). 그러면 세션·빌드가 필요 없어요.
- 설정에 "주소 변환" 카드가 있으면 좋아요: 주소 자료(날짜·곳 수 + [파일로 바꾸기]) · 웹에서 찾기(켜기·끄기) · 연결 확인([시험] + 마지막 성공).

## 6. 권하는 안

**개인정보 1안 + 순서 1안(내장 먼저, 행안부 웹은 표에 없을 때만) + 설정 "주소 변환" 카드.** 이유: 지금 되는 빠름·오프라인을 그대로 두고, "짐작"이던 후보만 정답으로 바꿔요.

확정되면 `wip/address-web` 세션이 할 일:
1. 주소정보누리집 검색 API 부르기 – 화면 `fetch` → JSONP → 앱 대신 보내기(`business.juso.go.kr`만) 순, 주소 글만 보내고 "파주시"를 앞에 붙임, 실패는 HTTP 200 안의 오류 칸으로 판단.
2. 승인키 두는 곳 – 설정 칸(사용자가 붙여 넣음, 암호화 파일에 저장), 처음엔 비어 있으면 웹 꺼짐.
3. `road_to_jibun` 결과에 출처(내장·웹)를 더하고, 표에 없을 때만 웹 결과를 후보 맨 위에 – 위치 칸·민원처리·엑셀 가져오기 세 곳 같은 규칙(엑셀은 줄마다 웹을 부르지 않고 표에 없는 줄만, 한 번에 몇 개씩).
4. 후보 목록 출처 배지("웹" / "내장 · 가까운 번호"), 파주 밖은 후보로만.
5. 설정 "주소 변환" 카드 – 자료 날짜·곳 수, [파일로 바꾸기](경기도 파일 → 파주시 줄 뽑기, 4만 줄 미만이면 멈춤), 웹 켜기·끄기, [시험](어느 길이 됐는지 표시).
6. 시험 값 – 기존 6개 그대로 + 웹 흉내(브라우저 미리 보기용) 몇 개, `cargo test` 통과.
7. 사양서 "민원대장 위치" 절·CLAUDE.md 주소 절·개인정보 규칙 한 줄 고침, 판 `AddressWeb.dc.html`은 민원대장·설정 기준판에 반영하고 지움.

## 7. 사용자가 회사 PC에서 시험할 것

1. 엣지로 https://business.juso.go.kr 이 열리는지.
2. (집이나 회사에서) 주소정보누리집 → 오픈API → **검색API** 승인키 신청 – 쓰는 곳 주소 칸에 무엇을 받아 주는지(`http://tauri.localhost`가 되는지) 화면을 찍어 주세요.
3. 키를 받은 뒤 회사 엣지 주소창에 `https://business.juso.go.kr/addrlink/addrLinkApi.do?confmKey=받은키&keyword=파주시 통일로 136&resultType=json` – 글자가 나오는지, 그 안에 "봉일천리"와 5·31이 있는지.
4. 같은 것을 `www.juso.go.kr/addrlink/addrLinkApiJsonp.do?confmKey=받은키&keyword=파주시 통일로 136&resultType=json` 로도 – 열리는지만.
5. (만든 뒤) 설정 "주소 변환" [시험] – 어느 길(화면·옛 방식·앱)로 됐는지, 걸린 시간.

## 8. 사용자 결정 (2026-10-21 09:24)

- 회사 PC에서 주소정보누리집 접속 확인, 검색API 승인키 받음(키는 문서·저장소에 적지 않아요 — 앱 설정 칸에 사용자가 붙여 넣어요).
- **순서 2안 – 웹 먼저, 웹이 안 되면 내장.** 개인정보는 1안(행안부만, 주소 글만)으로 이어 가요.

만들 때 규칙(`wip/address-web`):
1. 위치 글이 도로명주소처럼 보이면 웹에 먼저 물어요(화면 `fetch` → JSONP → 앱 대신 보내기). 3초 안에 답이 없거나 실패하면 내장 표로 바로 바꿔요.
2. 한 번 실패하면 10분 동안은 웹을 건너뛰고 내장만 써요(그 뒤 다시 시도). 설정 "주소 변환"에 마지막 성공·실패를 보여요.
3. 웹이 한 건으로 딱 맞으면 바로 바꿔요(내장과 달라도 웹을 믿어요 – 새판). 위치 칸에 마우스를 올리면 원래 글과 "웹"이 보여요.
4. 웹이 여러 건이면 후보 목록("웹" 배지), 웹에 없으면 지금 내장 규칙(바로 바꿈 또는 가까운 번호 3개, "내장" 배지).
5. 파주 밖은 웹 결과를 후보로만 보여요(지역 칸은 파주 목록이라 비움).
6. 보내는 것은 주소 부분만, 시·군이 없으면 앞에 "파주시"를 붙여요. 이름·연락처·민원 내용·뒤 글("앞", "일원")은 보내지 않아요.
7. 엑셀 가져오기·민원처리도 같은 규칙. 엑셀은 한 번에 4줄씩 묻고, 끝에 "웹 N · 내장 N"을 알려요.

9. 갱신: 분기 수동은 1년 한 번으로 줄이고, 설정 [파일로 바꾸기]로 빌드 없이 표를 바꿔요.
