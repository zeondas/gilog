# UI 모양 2차 검수 — 보이는 요소 전수조사 (0.15.0, 2026-10-18, UI 검사 세션)

1차([docs/qa/ui-0.15.0.md](https://github.com/zeondas/gilog/blob/main/docs/qa/ui-0.15.0.md))가 "코드에 적힌 값"을 세었다면, 이번엔 **실제로 그려진 결과**를 쟀어요. 화면·창 45개 × 테마 밝게/어둡게 × 배율 100%(물리 1600×900)/125%(물리 2000×1125) + 자료를 채운 상태(`-filled`, 밝게 100%·125%, 어둡게 100%) = **315장**, 보이는 요소 **60,035개**(선택자 403가지)를 `getBoundingClientRect`·computed style로 읽고, 글자는 1차와 같은 픽셀 재기(위 여백 − 아래 여백)로, 자식은 부모 안 위·아래·좌우 차이로, 125%는 물리 픽셀로 봤어요. 코드는 고치지 않았어요.

- 원자료: `census.json`(78MB, 7벌 모두) · 발견 목록 `findings.json` · 스크린샷 `shots2/<화면>-<light|dark>-<100|125>.png`(315장) · 어긋난 요소 조각 `cells2/`(1배·8배, 200쌍, 심한 순) · 스크립트 `census.py`(재기)·`analyze.py`(판정)·`report.py`(표) — 모두 `/tmp/claude-0/-home-claude/5c777991-2e74-5499-b8db-afb56a1c215f/scratchpad/audit/`
- 기준: 1차 4절 결정 ①~⑨(단추 34/28, 배지 22·6·11.5, 칩 네모 28, 글자 위−아래 0/−1, **100%·125% 둘 다**).
- 어둡게는 입력칸 placeholder 대비가 낮아 글자 재기가 덜 잡혀요(밝게 77.8% → 어둡게 84.0%). 모양은 두 테마가 같아서 아래 표는 밝게 기준이고, 어둡게에서만 다른 것은 따로 적었어요(없었어요 — 색 토큰 빠진 `.fx-up` 노란 배경만 어둡게에서도 그대로).

## 1. 요약

1. **글자 가운데 맞춤**: 밝게 100% 빈 상태 866곳 중 674곳 맞음(77.8%, 1차 74.1%와 같은 수준) · 125% 75.8% · 어둡게 84.0% · 자료 채움 77.1%. 어긋난 선택자 57가지 — 가장 많은 것은 여전히 **입력칸 −2**(`input.cell-input` 42곳, `.pr-in` 10, `.input` 5, `.input-sm` 3, `select.input` 3, `.jtalk` −4).
2. **자료를 채우면 입력칸 글자가 1px 더 올라가요**: placeholder는 −1이던 칸(`.input`·`.jday-in`·`.cell-input`·공사 관리 `.cell-input`)이 실제 한글을 넣으면 **−2**로 바뀌어요(5절). 1차가 placeholder로 잰 "−1·괜찮음"은 실제 글자 기준으로는 어긋남이에요 → `padding-bottom: 3px`(1차 E항)가 실제 글자 기준으로도 맞아요. 숫자 칸 `.num`(전화·날짜)은 반대로 −2 → −1로 좋아져요.
3. **1차에 없던 새 발견 ① 머릿기호 입력칸 글자가 반 픽셀에 떠 있어요**: `.bl-ed.cell-input` 안 줄(`.bl-line`)이 위 4.5 / 아래 3.5(100%) — `.bl-m { height: calc(var(--fs) * 1.5) }` = **19.5px**(app.css:3485)가 원인. 민원대장 내용·조치내용·할 일 세부정보·메모 창 모든 여러 줄 칸(108곳)에서 글자 가장자리가 흐려요.
4. **새 발견 ② 할 일 체크 동그라미는 첫 줄 글자보다 1px 아래**: `.td-check { margin-top: 1px }`(app.css:4273)로 18px 원이 18px 글줄보다 1px 내려가 있어요(192곳). 세부정보 아이콘 `.td-note-icon`도 `margin-top: 3px`로 같은 꼴(108곳). 사용자가 본 "⊕(15) vs 체크(18)"는 둘 다 **18px 상자**인데 ⊕는 svg 안 원이 반지름 9/24라 **그려진 지름이 13.5px**이에요(`TasksScreen.tsx:666`) — 크기 차이는 상자가 아니라 그림 안 원 크기예요.
5. **새 발견 ③ 집행현황 단위 토글은 100%에선 정확히 가운데**(위 3+1 / 아래 3+1)예요. 사용자가 본 "위로 붙음"은 **125% 전용 현상**: 높이 34→42.5·26→32.5 물리 px라 아래 가장자리가 반 픽셀에 걸려 흐려지고(위는 또렷) 단추가 내려앉아 보여요. 모서리가 둥근 상자는 크로미움이 패스로 그려 가장자리를 픽셀에 맞추지 않아요 — 같은 현상이 125%에서 62가지 선택자·2,062곳(위 또는 아래 한쪽만 흐림 1,023곳)에 있어요(4절).
6. **스위치**: 100%는 노브 위 2 / 아래 2로 가운데, 125%는 2.5/2.5 → 한쪽으로 반올림(사용자 신고와 일치). 트랙·노브가 `squircle`인 것(1차 그대로) + `.jcal-dot`도 같아요. `.search-x`·`.g-dot`·`.pr-run-dot`·`.cal-now::before`·`.rte ul>li::before`는 이번 화면에 안 보여 재지 못했어요(코드는 1차와 같음).
7. **125%에서만 생기는 글자 어긋남 18가지**: 배지·단추 글자는 1~2 물리 px **내려가고**(`.cm-hbtn` +2 57곳, `.cm-status` +1, `.chip` +1, `.td-src` +2, `.bd-chip` +2, `.btn-xs` +2, `select.cal-select` +2, `.fx-drop` +2) 입력칸 글자는 −3으로 **더 올라가요**. 1px 보정은 1.25 물리 px가 되어 반올림이 갈리기 때문이에요(4절).
8. **아이콘 크기**: svg 15가지 크기(10~18px)가 섞여 있어요 — 같은 뜻(지우기 ×)이 `.tool` 13 · `.tool-danger` 14 · `.pr-del` 14 · `.tool-box` 14 · `.chip-x` 11, 머리 줄 단추 안 아이콘 `.btn-ctrl` 16(업무일지)/12(민원대장)/14(분류 관리)/15(민원처리), 줄 안 단추 `.cm-memo` 16 · `.bd-memo` 15 · `.fx-ib` 13 · `.pr-icon` 15. 정한 것은 사이드바 15/17뿐(2-17표).
9. **종류 안에서 값이 흩어진 정도(그려진 값)**: 단추 높이 19가지·모서리 8가지, 입력칸 높이 12가지, 배지 높이 12가지·모서리 5가지, 표 머리 7가지, 토글 단추 26/32/34 — 1차 표와 같은 결론이고 결정 ①~⑤로 묶여요.
10. **스크롤바**: 실제로 스크롤이 생긴 컨테이너는 `main.main`(설정·채운 민원대장·할 일), `.cal-wk-scroll`(주 보기), `.fx-rn-body`(일괄 이름 바꾸기), `.dialog-body` 네 곳뿐이고 **모두 브라우저 기본 막대**(헤드리스 15px, 윈도우 WebView2 17px)예요. 집행현황 `.bd-scroll`은 `scrollbar-width: thin` + `::-webkit-scrollbar 14px`를 함께 적었는데 **크로미움 121부터 `scrollbar-width`가 있으면 `::-webkit-scrollbar`는 무시**돼요(이 크로미움 141에서 10px 얇은 막대로 확인) → 둥근 14px 막대는 실제로 안 그려져요. 가로 스크롤은 어느 화면·상태에서도 안 생겼어요(민원대장 열은 `fitWidths`가 표 폭에 맞춰 줄여요 — 가로 스크롤이 날 수 없음).
11. **색 토큰 밖**: 그려진 색 기준으로 `.fx-up` 배경(밝게·어둡게 모두 #FFF3D6), 일괄 이름 바꾸기 창의 네이티브 체크박스(`FilesDialogs.tsx:329-330` '대소문자 구분'·'정규식')는 `accent-color`가 없어 **크롬 기본 파란 체크**로 그려져요(앱 보라가 아님), 캘린더 `.cal-day.out`·주 보기 `.cal-ev.dot` 배경(`color-mix` 계산값이라 토큰 그대로 판정 불가 — 문제 아님). 1차의 파일 아이콘 12색은 탐색기 svg 안 색이라 이번 재기 밖(결정 ⑦ 그대로).
12. **업무일지 전화번호 단추 `.jtel`**: 카드 기둥 안에서 위 8 / 아래 0(158곳) — `margin: auto 0 0; padding-top: 8px`로 기둥 **아래에 붙이는 설계**라 어긋남이 아니라고 봐요(애매함으로 둠).
13. **자료 채움에서 커지는 것**: 민원대장 위치 칸 복사 단추 `.cm-copy` 22 → 58(세 줄 주소), `.bl-ta` 20 → 40, `.bl-ed` 28 → 127(3줄 머릿기호) — 늘어나도 옆 칸 글자 위치는 같았어요. 프로젝트 칩 20개가 두 줄로 넘어가도 `.pchip` 28 유지, 40자 프로젝트 이름은 `.pbadge-t` 말줄임 유지(업무연락처·업무일지 배지 높이 그대로), 연번 1546은 1차대로 두 줄로 꺾여요(폭 44).
14. **125% 반 픽셀 자식 위치**(부모 안 자식 위·아래 ×1.25가 .5): 34가지 선택자 — 스위치 노브(2→2.5), 사이드바 아이콘(10→12.5), 머리 줄 단추 아이콘(6→7.5), `.pbadge-t`(2→2.5), `.cell-input`이 `.cm-c` 안에서(2→2.5), `.bd-memo`·`.btn-add`·`.tb`·`.tool-box` 아이콘(6→7.5). 배경 있는 자식(노브·배지 글자)은 눈에 띄고 선 아이콘은 덜 보여요.
15. **고칠 방법은 6절** — app.css 공통 규칙 12개(파일:줄)로 모았고, 125% 전용 보정은 1안/2안으로 사용자 결정이 필요해요.

**1차에 없던 새 발견 목록**: ① `.bl-m` 19.5px 반 픽셀(머릿기호 칸 전부) ② `.td-check`/`.td-note-icon` margin-top으로 1px 처짐 + ⊕ 그려진 지름 13.5 ③ 단위 토글은 100% 정상·125% 가장자리 흐림(둥근 상자 공통) ④ 125%에서 배지·단추 글자 +1~2, 입력칸 −3 ⑤ `scrollbar-width`가 `::-webkit-scrollbar`를 무력화 ⑥ 실제 글자를 넣으면 입력칸 −1 → −2 ⑦ 일괄 이름 바꾸기 창 네이티브 체크박스가 크롬 기본 파랑(`accent-color` 없음) ⑧ 아이콘 크기 15가지 ⑨ `.jproj-badge` 높이 21(홀수)·`.side-item` 35(홀수) → 125%에서 43.75px로 양쪽 가장자리 흐림.
## 2. 요소 종류별 표 (밝게 100% 빈 상태의 그려진 값 · 치우침은 100%/125% 모두)

## 7. 애매함 (판정 안 함 — 사용자 결정)

- `.jtel`(업무일지 기둥 전화번호) 위 8/아래 0 — 아래에 붙이는 설계로 봐요.
- 할 일 줄 `align-items: flex-start`는 제목이 두 줄일 때를 위한 것이라 6-3처럼 margin만 손봐요.
- 125% 가장자리 흐림(6-7)은 모든 둥근 상자에 해당해 "값을 4의 배수로"가 아니면 없앨 수 없어요 — 결정 ①④와 충돌.
- 아이콘 크기(6-12)는 정한 값이 없어 어긋남이 아니라 "정할 것"이에요.
