# 로드킬 다발구간 분석 – 기록 앱 적용 검토 (2026-10-30 우두머리 세션, 검토만)

사용자가 다른 사업(동물 찻길 사고 예방 울타리 설치)에서 Python으로 검증한 처리 흐름을 기록 앱에 넣을 수 있는지 검토한 글이에요. **반영하기로 한 것은 아니에요** – 결정되면 공통 결정 로그·대기 목록에 적고 세션을 열어요.

## 0. 먼저 바로잡을 것
- 검토 요청 문서는 기록 앱을 "C# WPF, .NET 10"으로 적었는데 **아니에요**. 기록 앱은 Tauri 2(Rust) + React(TypeScript)예요. 저장은 Rust `core`(SQLCipher), 엑셀 읽기 `calamine`·쓰기 `rust_xlsxwriter`, zip, 인터넷 요청 `reqwest`가 이미 들어 있어요. 그래서 "C# 안에서 처리 / Python 실행파일 동봉"의 비교는 "Rust 안에서 처리 / Python 동봉"으로 바뀌어요.
- 카카오 로컬 API는 10-19 지도 모듈 검토·10-2x 주소 변환 검토([address-web.md](address-web.md))에서 이미 한 번 다뤘어요 – 민원 위치가 민간 회사 기록에 남는 걸 꺼려 행안부(주소정보누리집)를 1순위로 정했어요. 로드킬 자료는 민원인 정보가 아니라 사고 위치라 성격이 다르지만, 같은 잣대를 한 번 대어 봐야 해요.
- 원자료 엑셀이 DRM이면 못 열어요(사용자 규칙: DRM 파일은 미리 알리고 확인). 앱은 열리지 않을 때 "보안 해제 뒤 다시" 안내만 할 수 있어요.

| 안 | 내용 | 좋은 점 | 걸리는 점 | 권함 |

### ④ 노드링크 갱신
| 안 | 내용 | 좋은 점 | 걸리는 점 | 권함 |
| --- | --- | --- | --- | --- |
| 1안 | **zip을 고르면 파주 범위만 잘라 앱 자료 폴더에 작은 파일로 저장(원본은 두지 않음)**, 설정에 "노드링크 날짜" 표시 | 260MB 원본을 안 들고 다님(잘라낸 4.4만 링크는 약 5~10MB), 다음부터 바로 | 자르는 데 1~2분(진행 막대 필요), 범위 밖(예: 양주 경계)이 필요하면 다시 zip 골라야 함 | ✔ 매번 900MB를 읽을 수는 없어요. 범위는 설정값(경위도 네 수)으로 빼요 |

### ⑤ 지오코딩 공급자
| 안 | 내용 | 좋은 점 | 걸리는 점 | 권함 |
| --- | --- | --- | --- | --- |
| 1안 | **공급자 한 겹**(10-19 지도 모듈 결정과 같은 모양) – 처음은 카카오, 뒤에 행안부·브이월드·오프라인(위치정보요약DB)을 끼울 수 있게. 캐시·보정표는 공급자와 무관 | 업무망/인터넷망 분리에 대비, 10-2x 주소 변환(행안부 1순위)과 맞춤 | 처음부터 한 겹 더 설계 | ✔ 이미 같은 결정을 두 번 했어요 |
| 2안 | 카카오만 | 가장 빠름 | 망 분리되면 기능 전체가 멈춤, 약관(결과 저장) 확인 필요 | |

**확인 필요(카카오)**: 카카오 로컬 API 결과(좌표)를 DB에 저장해 재사용하는 "주소 캐시"가 약관상 허용되는지 – 지도 API 운영정책은 검색 결과의 저장·재가공을 제한하는 쪽이라 **캐시를 "보정표(담당자가 확인한 값)"로만 남기는 형태**가 안전해요. 세션을 열면 첫 일로 약관 원문을 확인해요. 무료 쿼터(일 10만·월 30만 언저리, 2025 개편)는 2,121건 × 최대 3회 호출 = 6천 건 안쪽이라 넉넉해요.

## 2. 개발 단계(기능 세션 원칙 – 한 세션 한 단계, 각 단계는 정답지 `로드킬_정규화_분석_v3.xlsx`와 맞대어 시험)

| 단계 | 목적 | 완료 조건 | 시험 |
| --- | --- | --- | --- |
| A 틀·설정 | "분석" 모듈 자리, `rk_*` 표, 사전·기준값 화면(엑셀 가져오기/내보내기), 칼럼 대응표 | 설정 화면에서 사전을 고치고 저장·백업에 들어감 | core 시험(표·마이그레이션 `SCHEMA_VERSION`+1), 지킴이 새 장면 |
| B 읽기·정규화 | 원자료 엑셀 → 정규화 칼럼(주소 정제·유형 판정·읍면 보완·도로 칸·종·품질 표시) | 2,121행 정규화 결과가 정답지 "정규화_전체" 시트와 **칸 단위로 같음**(다른 칸 0) | Rust 시험에 원자료 일부(개인정보 없는 50행)를 고정값으로 넣기 + 전체는 부하 시험처럼 따로 |
| C 지오코딩 | 공급자 한 겹 + 카카오 구현, 캐시·보정표, 실패·검토필요 표시 | `geocode_result.csv`와 좌표 일치(1,961 성공) · 회사 망에서 호출 확인(공휴일 받기처럼 화면 쪽 fetch가 필요할 수 있음) | 캐시 가득 채운 상태에서 호출 0회 확인 |
| D 도로 매칭 | zip → 파주 범위 자르기·저장, 반경 150m 도로명 우선 매칭, 연접 판정 | 링크 수 4.4만, 연접 1,271/412/278 재현 | TM 좌표 변환 시험값(원점·몇 점) |
| E 다발구간·출력 | 반경 500m 묶기(전체·야생동물), 반복 신고 지점, 엑셀 7시트, 지도 HTML(브라우저로 열기) | 상위 결과 재현(율곡로 6·5, 통일로 92·파주로 76·자유로 72), 엑셀·HTML이 정답지와 같은 구조 | 회귀 기준값을 시험에 고정 |

예상: Rust로 옮기는 분량은 Python 참고 코드 10개 파일 기준 작업일 5~7일(세션 5개), 지도 HTML은 기존 `파주시_로드킬지도_v1.html` 틀을 그대로 써요.

## 3. 위험
| 위험 | 내용 | 줄이는 법 |
| --- | --- | --- |
| 대용량 shp | 900MB 압축 해제·읽기 1~2분, 메모리 수백 MB | zip 안에서 스트리밍으로 읽어 범위 밖은 바로 버림, 한 번만(④1안), 진행 막대 |

| 좌표계 | ITRF2000 중부원점 TM → 경위도 변환 오차 | 공식 구현 뒤 알려진 점(시청 등) 3곳으로 검산, 또는 `proj4rs` |
