## 4. 코딩할 때 지킬 것 (승인 뒤)

- 가지 `wip/parts`(main 최신에서 새로). 빌드 묶음 직후 main이 조용할 때 시작.
- 한 묶음 = 부품 하나(또는 ③에서 고른 크기) + 끼우는 화면 전부 → 캡처 비교·동작 검사 → `check.yml` 통과 → "끝(합치기 기다림)" → 빌드 → 다음 묶음.
- 그 화면을 고치는 기능 세션이 열려 있으면 현황판에 "공통 부품이 ○○ 파일을 고치는 중"을 적고 시작해요(겹치면 빌드 세션이 합칠 때 충돌).
- `VirtualList`가 들어간 표(민원대장·업무연락처)는 줄 그리는 부분을 건드리지 않아요.

| 동작 실수(Esc 빠짐 등) | 화면마다 따로 남음(지금 Esc 없는 곳 4) | 한 번 고치면 전부 |
| 부품을 잘못 고침 | 한 화면만 틀림 | **모든 화면이 한꺼번에 틀림** – 그래서 8-3의 지킴이가 꼭 필요 |
| 틀어졌을 때 되돌리기 | 화면마다 | 부품 한 곳 |

UI 검사에서 화면마다 모양이 조금씩 달랐던 것(메뉴 4가지, 빨간 테두리 4가지)이 바로 따로 만든 데서 생긴 거예요. 합치면 같은 일이 다시 생길 길이 줄어요.

### 8-3. 맞춰 둔 간격을 지키는 법 – "모양 지킴이"

| 무엇 | 내용 |
| --- | --- |
| 기준 사진 | 지금 main(0.29.0)으로 모든 화면 + 띠·메뉴·날짜 칸이 열린 장면을 100%·125%로 찍어 둠. 이게 "맞는 모양" |
| 비교 | 고친 뒤 같은 장면을 다시 찍어 한 점씩 뺌 → 다른 점이 0이어야 통과. 다르면 어디가 몇 px인지 빨갛게 표시 |
| 글자 가운데 재기 | 이미 있는 `tools/align`(UI 검사 때 만든 자)을 같이 돌림 – 칸·단추 글자 자리가 그대로인지 |
| 누가 쓰나 | 이 세션만이 아니라 **모든 세션이 화면을 고친 뒤 돌림**(빌드 전 검사에 넣을 수 있음) – 다른 세션이 기능을 고치다 간격을 틀어도 잡힘 |
| 못 잡는 것 | 윈도우에서만 보이는 것(실제 125% 글꼴 그리기·한글 입력) – 빌드 뒤 사용자 시험 목록으로 |

### 8-4. 코드가 얼마나 줄어드나 (솔직하게)

| 부품 | 줄어드는 양(어림) |
| --- | --- |
| 바깥 닫기 | 약 250줄 |
| 묻는 띠 | 약 150줄 |
| 날짜 칸 | 약 120줄 |
| 메뉴 | 약 350줄(메뉴에 들어갈 줄 목록은 남음) |
| 합계 | **약 850줄 – 화면 코드 19,226줄의 4~5%** |
| CSS | 1단계(모양 그대로)는 거의 안 줄어요. 모양까지 맞추면 200~250줄(2%) |

크게 줄어드는 것은 아니에요. 이 넷의 값은 "앞으로 같은 일을 한 번만 하는 것"이에요. 더 크게 줄일 곳은 따로 조사해야 해요: 고르기 목록 8개(약 400~500줄 어림), 집행현황·예산현황 표가 겹치는 부분(조사 전).
