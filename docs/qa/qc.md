## 0. 시험 준비 (실행 세션이 가장 먼저 해요)

### 0-1. 집 컴퓨터 상태 확인
1. 데스크톱 앱이 켜져 있고 이 세션에 컴퓨터가 연결돼 있는지(`get_device_info`). 컴퓨터 사용(computer use)을 켜고 화면 1920×1080·배율 100%인지 캡처로 확인해요(배율이 100%가 아니면 윈도우 설정 › 디스플레이에서 100%로 – 모양 기준은 100% 하나예요, 결정 10-21 14:36).
2. 기존 기록앱이 설치돼 있으면 **자료를 지워도 되는 컴퓨터**임을 전제로 그대로 둬요(제거 뒤 다시 설치하는 쪽이 깨끗해요 – 제거 창에서 "기록 자료도 지우기"를 켜고 제거, 그다음 새로 설치). 윈도우 한글 입력기(Microsoft IME)가 기본 입력기인지 확인해요.
3. 시험 파일 폴더 `D:\qc\`(D:가 없으면 `C:\qc\`)를 만들어요. 아래 자료 파일은 모두 여기에 둬요. 탐색기 시험용 `D:\qc\fx\`도 만들어요(0-4).

### 0-2. 설치·처음 시작
1. 설치 파일 `giLog_0.64.0_x64-setup.exe`(Releases build-84 – 회사가 아니라 집 컴퓨터라 https://github.com/zeondas/gilog/releases/tag/build-84 에서 바로 받아도 돼요. 세션에서 받을 때는 CLAUDE.md "말투와 형식"의 `gh api … assets/<id>` 방법)를 `D:\qc\`에 받아 두고 두 번 눌러요.
2. 설치 창: 묻는 쪽 없이 520×400 창 하나, 위 보라 띠에 흰 ㄱL 심볼과 "기록", 띠 왼쪽 위 버전 0.64.0, "설치하는 중…"과 보라 진행 막대 → "설치를 마쳤어요 / 곧 기록이 열려요" → 2초 뒤 기록이 열리고 설치 창이 닫혀요(사양 › 기술 구성 "설치·제거 창"). 바탕화면·시작 메뉴에 "기록" 바로 가기가 생겨요. 끝에 "기록 빠른 찾기" 관리자 허용 창이 뜨면 **허용**해요(탐색기 빠른 찾기 시험에 필요).
3. 처음 열리면 비밀번호 정하기 화면이에요. 시험 비밀번호 **`qc1234!`** 로 정해요(실행 세션이 결과 표 맨 위에 적어 둬요). "암호를 잊으면 자료를 되찾을 방법이 없어요" 문장이 보이는지 봐요(사양 › 저장과 암호화).
4. 열리면 시작 화면이 **업무일지**인지(처음 값), 창이 1600×900으로 화면 가운데 떠 있는지, 최대화가 아닌지 봐요(사양 › 화면 틀). 이것이 WN-01·WN-02라 결과 표에도 적어요.
5. 설정 › 일반 › 내 이름을 **"전훈민"** 그대로 두고, 설정 › 모듈이 모두 켜져 있는지 봐요.

### 0-3. 저장 위치·백업 폴더
- 자료 파일: `문서\giLog\gilog.db`(암호화), 백업: `문서\giLog\backup\gilog_YYYY-MM-DD.gilogbak`(잠금 풀 때 하루 1개·최근 7개), `…_before-import.gilogbak`(백업 불러오기 전), `…_before-clear.gilogbak`(자료 지우기 전), `…_before-vN.gilogbak`(형식 올리기 전). 앱 설정: `%LOCALAPPDATA%\giLog\prefs.json`·`window.json`·`pin.bin`·`key.json`. 설치 폴더: `%LOCALAPPDATA%\giLog`. 빠른 찾기 도우미: `C:\Program Files\giLog Search\`(log.txt).
- 시험 시작 전 `문서\giLog\backup\`에 **오늘 날짜 백업 1개**가 생겼는지 적어 둬요(LK-07·ST-30의 기준값).
- 민원처리 폴더(처음 값): `D:\민원처리`·`D:\민원처리\가져오기`·`D:\민원처리\보내기`. D:가 없으면 설정 › 민원처리에서 `C:\qc\민원처리`로 바꿔요(PR-02).

## 15. 실행 세션용 판정 틀 · 우선순위

### 판정
- **통과** – 기대 결과 그대로. **실패** – 다름(캡처 필수). **보류** – 환경이 없어 못 함(한글 프로그램·외부 계정·USB·Hello 없음)이나 시간이 모자라 안 함(까닭 한 줄).
- 자동 항목은 돌리지 않고 "자동"으로 적어요(check.yml·빌드 세션이 통과를 확인했어요). 사람 항목은 "사람"으로 적고 0-5의 준비물을 끝 절에 모아요.
- 캡처: `D:\qc\result\qc_<번호>.png`(예 `qc_CM-27.png`), 한 항목에 둘 이상이면 `qc_CM-27_2.png`. 실패마다 꼭, 통과는 화면별 처음·끝 한 장(`qc_CM_ok.png`)만.
- 결과 표: `docs/qa/qc-result-0.64.0.md`에 이 문서와 같은 번호 순으로 `번호 | 판정 | 본 것(한 줄) | 캡처`. 맨 위에 시험 날짜·컴퓨터(해상도·배율·윈도우 판)·설치 파일·비밀번호(`qc1234!`)·걸린 시간, 맨 아래에 화면별 통과/실패/보류 수 표와 "다음 대기 목록 ✔ 후보"(실패를 화면별로 한 줄씩 – 우두머리가 그 화면 칸에 옮겨요). 올리기는 main `[skip ci]`(문서만), 현황판 "QC 실행" 줄도 고쳐요.
- 실패 중 자료가 깨지는 것(저장 안 됨·값 바뀜·백업 안 생김)은 결과 표 맨 위에 **굵게** 따로 모아요.
- 같은 원인으로 보이는 실패가 여럿이면 하나에 적고 나머지는 "CM-27과 같음"으로.
- 시험 중 앱이 멈추거나 꺼지면 그 항목 실패 + 앱 로그(`%LOCALAPPDATA%\giLog\` 아래)와 윈도우 이벤트 뷰어 응용 프로그램 오류를 캡처해요.

### 우선순위 (밤 6~7시간에 다 못 돌 때 – 위에서부터)
