#가. Claude Code 넣기
○ 회사 망은 설치 명령이 막혀 있어, 미리 받아 둔 claude.exe 파일을 정해진 폴더에 직접 넣는 방식
1) claude.exe 파일 받기 : 【확인 필요】 사용자가 파일로 전달 또는 Claude에게 "윈도우용 Claude Code 설치 파일" 요청
2) 파일 탐색기 주소 칸에 %USERPROFILE% 입력 후 Enter (내 폴더가 열림)
3) 내 폴더에 .local 폴더를 만들고, 그 안에 bin 폴더를 만듦
4) bin 폴더에 claude.exe를 넣음
5) claude.exe를 두 번 눌러 실행, 검은 창의 안내대로 로그인(브라우저가 열리면 Claude 계정으로 로그인·허용)
6) 로그인을 마치면 검은 창을 닫음
- .local 이름이 만들어지지 않으면 끝에 점을 하나 더 붙여 .local. 로 입력
- 기록은 이 자리를 먼저 찾으므로 설정의 "Claude 실행 파일" 칸은 처음 값(claude) 그대로 둠
- 다른 자리에 넣었으면 그 파일 위치를 "Claude 실행 파일" 칸에 적음

#라. 신문고 로그인
○ AI는 크롬에 로그인되어 있는 업무처리포털을 그대로 씀
1) 기록 › 민원처리 머리 줄 [신문고 열기]를 누름
2) 크롬에 업무처리포털이 열리면 로그인
3) 로그인한 크롬 창은 그대로 두고 [민원 불러오기]를 누름
- 로그인이 풀리면 기록이 멈추고 "신문고 로그인이 풀려 있어요" 안내, 다시 로그인 후 진행
#마. 폴더 확인
○ AI가 읽은 민원과 첨부 사진이 오가는 폴더
1) 설정 › 민원처리 카드에서 민원 폴더·가져올 폴더·다운로드 폴더·보낼 폴더 확인
2) 다운로드 폴더는 크롬이 파일을 받는 폴더와 같게 맞춤
3) 처음 첨부를 받을 때 크롬이 "여러 파일 다운로드"를 물으면 허용
#바. 준비가 덜 되었을 때 뜨는 글

2) "Claude Code 로그인이 필요해요" : claude.exe를 다시 실행해 로그인
3) "크롬을 찾지 못했어요" : 크롬 설치
4) "Claude가 크롬에 붙지 못했어요" 또는 "크롬의 Claude 확장과 이어지지 않았어요" : 크롬을 켜고 확장 로그인 확인, 엣지 확장은 끔
5) "Claude가 크롬 화면을 읽지 못했어요" : 크롬 확장 켜짐·엣지 확장 꺼짐 확인
6) "신문고 로그인이 풀려 있어요" : [신문고 열기]로 다시 로그인
7) "못 찾은 사진 N개" : 다운로드 폴더와 크롬 자동 다운로드 허용 확인
8) "인터넷 연결이 막혔어요(회사 프록시·보안 프로그램)" : 【확인 필요】 회사 망에서 막힌 경우, 정보통신 담당 부서에 문의
9) "Claude 사용 한도에 걸렸어요" : 잠시 뒤 다시 누름

#가. 구글 콘솔 앱 설정 (콘솔 관리자, 처음 한 번)
○ 구글 클라우드 콘솔(console.cloud.google.com)에서 기록용 앱을 한 번 만들어 두는 일, 이미 만들어 두었으면 건너뜀
1) 구글 클라우드 콘솔에 로그인해 프로젝트를 하나 만듦
2) 사용할 기능(API)에서 Google Calendar API를 사용 설정, 팀 공유까지 쓰면 Google Sheets API·Google Drive API, 구글 할 일로 보내기까지 쓰면 Google Tasks API도 사용 설정
3) OAuth 동의 화면(구글 인증 플랫폼)에서 앱 이름·지원 메일을 넣고 대상은 "외부", 게시 상태는 "테스트"
4) 데이터 액세스(권한)에 캘린더(앱이 만든 캘린더만), 필요하면 할 일·스프레드시트·드라이브 파일·메일 주소 권한 추가
5) 클라이언트를 "데스크톱 앱" 종류로 만들고 JSON 파일(client_secret…json)을 받음
- 받은 JSON 파일은 남에게 퍼뜨리지 않음
- 【확인 필요】 지금 콘솔의 게시 상태·만든 클라이언트 종류

다. 집행현황만 나가고 민원인 정보는 나가지 않음

@큰 3. 준비 항목
가. 사람마다 : 구글 계정, 테스트 사용자 등록(제3장 나.), 같은 앱 정보가 든 기록
나. 호스트 : 팀 공유 켜기 → 새로 만들기 → 명단에 팀원 더하기 → 새로고침 → 주소 복사 (팀에 한 번)
다. 팀원 : 팀 공유 켜기 → 받은 주소 붙여 넣고 연결 (사람마다 한 번)
@상세
#가. 사람마다 필요한 것
○ 팀 공유는 구글 캘린더 연동과 같은 앱 정보·같은 구글 로그인을 씀
1) 구글 계정이 있어야 함
2) 그 메일이 구글 콘솔 테스트 사용자에 등록되어 있어야 함 (제3장 나.)
3) 모두 같은 앱 정보가 든 기록을 씀 (같은 설치 파일 또는 같은 JSON 파일)
- 구글 캘린더 연동을 쓰지 않는 사람도 팀 공유를 켤 때 구글 로그인을 함, 이때 캘린더 내보내기는 꺼진 채로 시작
- 켤 때 구글 시트 권한을 한 번 더 받으며 "확인하지 않은 앱" 경고가 뜨면 그대로 진행
#나. 호스트 (팀에 한 사람)
○ 공유 시트를 만들고 팀원에게 권한을 주는 사람
1) 설정 › 집행현황 카드 › 팀 공유 켜기
2) [새로 만들기]를 누르고 브라우저에서 구글 로그인을 마침
3) "함께 쓰는 사람"에 팀원 이름과 구글 메일을 넣고 더함
4) 집행현황 화면 [새로고침]을 눌러 팀원에게 권한을 줌
5) [주소 복사]로 시트 주소를 복사해 팀원에게 보냄
- 팀원을 더하면 구글이 그 메일로 시트 안내를 보냄
- 명단에서 빼면 다음 새로고침 때 권한을 거둠
[그림] 팀 공유 – 함께 쓰는 사람 명단
<그림>
#다. 팀원
○ 호스트가 보낸 주소로 공유 시트에 연결하는 사람
1) 설정 › 집행현황 카드 › 팀 공유 켜기
2) 호스트가 보낸 시트 주소를 붙여 넣고 [연결]
3) 브라우저에서 명단에 등록된 구글 계정으로 로그인
4) "연결했어요" 확인 후 집행현황 화면에서 호스트의 집행현황이 들어왔는지 확인
- 집행현황 화면이 열려 있는 동안 5분마다 저절로 새로고침, 빨리 보려면 [새로고침]
#라. 준비가 덜 되었을 때 뜨는 글
○ 팀 공유 줄이나 집행현황 화면에 뜨는 글과 할 일
1) "함께 쓰는 사람 명단에 내 구글 메일이 없어요" : 호스트에게 명단에 더해 달라고 함
2) "시트를 열 수 없어요" : 호스트가 명단에 더한 뒤 [새로고침]을 했는지 확인
3) "시트를 찾지 못했어요" 또는 "시트 주소를 읽지 못했어요" : 호스트가 보낸 주소를 그대로 다시 붙여 넣음
4) "구글 로그인이 풀렸어요 – 설정 › 집행현황에서 다시 연결해 주세요" : 다시 연결 (테스트 상태에서는 약 7일마다)
5) "인터넷에 연결하지 못했어요" : 고친 것은 내 컴퓨터에 두었다가 다음 새로고침 때 올림, 【확인 필요】 회사 망에서 막히는지
6) 구글 로그인 화면에서 막힘 : 그 메일이 테스트 사용자에 등록되었는지 콘솔 관리자에게 확인
