# 글자 가운데 맞춤 재기 (tools/align)

박스·배지·버튼·입력칸 안에서 글자가 칠해진 부분의 위·아래(좌·우) 여백을 픽셀로 재는 도구예요. 2026-10-17 세션이 만들었어요.

- 기준: 1920×1080, 배율 1(사용자 PC 100%). 글꼴은 사용자 PC와 같아야 해요 — Pretendard를 앱에 넣기 전에는 Noto Sans KR(구글 폰트 `NotoSansKR[wght].ttf`를 `~/.fonts`에 넣고 `fc-cache -f`).
- 맞음 = 위 − 아래 가 0 또는 −1 (남는 1px은 아래, 사용자 1안).

## 쓰는 법 (2026-10-30 ②-3 3차 – 미리 보기 = WASM core)
1. 미리 보기를 빌드해요: `npm run build:wasm`(또는 check.yml 산출물 `preview-wasm`을 `src/wasm-pkg/`에 풀기) → `npx vite build -c tools/guard/vite.config.ts --outDir <작업 폴더>/site`. 앱 코드는 고치지 않아요(옛 방식 – 앱 코드에 흉내 한 줄 넣고 빌드 – 은 없어졌어요).
2. `<작업 폴더>/site`를 `python3 -m http.server 5175`로 띄워요.
3. 도구가 `seed.js`(실제 앱 명령으로 예시 자료를 채우는 `window.__previewSeed`)를 페이지에 넣고 재요 – 아래 census.py·ruler.py·topbar*.py.

`jtel`(업무일지 연락처 글줄)과 `cal-ev dot`(주 보기 여러 줄 일정)은 박스가 아니라 빼고 봐요. 괄호·숫자가 섞인 글은 글자 모양 때문에 1px 차이가 남아도 괜찮아요(사용자 확정).

## census.py · report.py (2026-10-18 UI 통일 세션 — 지금 쓰는 도구)
예전 1920×1080 도구(`run2.py`·`measure.py`)는 돌아가지 않아 2026-10-30에 지웠어요. 지금은 아래 둘을 써요.

- 기준: **1600×900**, 배율 **1과 1.25** 둘 다(2026-10-18 결정), 밝게·어둡게. 맞음 = 물리 픽셀로 위 − 아래가 0 또는 −1. 숫자만 있는 칸은 +1 허용(사용자 확정).
- 미리 보기 띄우기는 위 1~2번과 같아요(WASM 미리 보기 빌드 → 5175에 띄우기).
- `python3 census.py 결과.json [light|dark] [1|1.25] [filled]` — 사이드바의 모든 화면 + 분류 관리·프로젝트 관리·종류 관리·일정 상세·공사 관리·민원 메모·설정 스크롤 5장을 재요. `filled`면 빈 글 칸에 한글(날짜 칸은 숫자)을 넣고 재요 — 실제 쓰는 모양은 이쪽이에요. 뜨는 창이 있으면 창 안만 재요(뒤 흐린 요소 제외). 스크롤바를 켜고(`--hide-scrollbars` 끔) 찍어요.
- `ALIGN_CSS=시험.css python3 census.py …` — CSS를 덧붙여 재요(고치기 전 시험).
- `python3 report.py 결과.json …` — 맞는 비율과 어긋난 묶음(태그·첫 클래스·값)을 보여 줘요.
- 알아 둘 것: 입력칸 글자는 여백 1px을 바꾸면 위−아래가 **2씩** 바뀌어요(글자 상자가 가운데로 가니까). 그래서 0/−1 사이 값이 없는 곳이 있어요 — 한글 0, 숫자 +1이 되는 쪽(여백 0)을 골랐어요. 125%는 `@media (min-resolution: 1.25dppx)` 안에서 0.8px(물리 1px) 단위로 따로 맞춰요(app.css 맨 끝).
- 2026-10-18 결과(`wip/ui`): 100% 밝게·어둡게 90.4%(271곳 중 245) · 125% 68.8%(272곳 중 187, 보정 전 45.6%). 남은 것: 숫자 칸 +1(허용), `kb-cap`의 'Ctrl'·괄호 든 글(허용), 사이드바·아이콘 섞인 단추(재기 한계 — 눈으로 확인).

## ruler.py · 기준선 자 `?ruler` (2026-10-18 UI 통일 — 입력칸 글자 높이의 기준)
- 앱 주소 끝에 `?ruler`를 붙이면(빌드에도 들어 있는 숨은 모드, `src/ruler.ts`) 화면의 모든 입력칸·자리글·머릿기호 칸·배지에 파란 테두리와 **빨간 기준선**을 덧그려요. 같은 줄(가운데 y 8px 안)의 칸끼리 기준선이 0.5px 이상 벌어지면 노랑. 콘솔에서 `__ruler()`를 부르면 표(칸 이름·d·칸 높이·줄 높이·기준선·devFrac·벌어짐)를 찍어요.
- 재는 것은 잉크가 아니라 **글자 상자**(글꼴의 위·아래): 입력칸·여러 줄 칸은 `document.caretPositionFromPoint(...).getClientRect()`(브라우저가 실제로 놓은 커서 상자), 배지는 `Range.getClientRects()`. `d` = 글자 상자 가운데 − 칸 가운데(CSS px), `devFrac` = 기준선이 물리 픽셀에서 걸린 소수 자리.
- `python3 ruler.py 결과.json [1|1.25] [light|dark] [--shots 폴더]` — 모든 화면 + 관리 창·일정 상세·공사 관리·민원 메모·할 일 신규·설정 스크롤을 돌려 저장하고, 벌어진 줄을 찍어요. 미리 보기 띄우기는 위 census.py 절과 같아요.
- 잉크 재기(census.py)는 그대로 두지만 기준은 이쪽이에요.
- 알아 둔 것: 크로미움의 `<input>`은 `line-height`를 쓰지 않고 글자 상자(Pretendard 13px → 정수 15px)를 안 높이 가운데에 놓아요. 안 높이가 짝수면 0.5px에 걸려요 → 한 줄 칸은 아래 여백 1px로 안 높이를 홀수(25·31)로 둬요(app.css "한 줄 칸 한 규칙").
- 2026-10-18 결과: 전(0.16.0) 100%에서 벌어진 줄 3개(민원대장 신규 줄·업무연락처 신규 줄·업무일지 새 카드), 125%에서 1개(민원대장 신규 줄 183.7/184.5/184.7) → 후 0개·0개, 28칸 85곳 모두 d = −0.5(남는 1px은 아래), devFrac 0.
